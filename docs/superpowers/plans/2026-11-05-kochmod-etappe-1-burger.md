# Kochmod Etappe 1 (Burger komplett) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Minecraft Bedrock add-on in which a child grills a patty, slices a tomato, assembles a hamburger or cheeseburger on a counter and serves it to a guest who pays emeralds or grumbles.

**Architecture:** A behavior pack and a resource pack under `packs/`. All game rules live in pure JavaScript modules (`packs/BP/scripts/logic/`) that take plain data and return plain data, tested with `node --test`. Thin glue modules (`packs/BP/scripts/world/`) connect them to the Script API: custom block components, world dynamic properties, forms, entities. Block states are only a *view* derived from stored station state. Textures are generated by a Node script from sprite definitions.

**Tech Stack:** Minecraft Bedrock 1.26.62 (Windows release build), `@minecraft/server` 2.0.0, `@minecraft/server-ui` 2.0.0 (stable only), plain ES-module JavaScript with JSDoc types, Node 24 (`node:test`, `node:zlib`), dev dependencies `typescript` (checkJs only), `@minecraft/server`, `@minecraft/server-ui`, `adm-zip`.

**Spec:** `docs/superpowers/specs/2026-11-05-kochmod-design.md` (German). This plan covers §14 Etappe 1 only. Etappen 2–3 get their own plans.

## Global Constraints

- Namespace `kochmod` for every identifier.
- Stable APIs only: no experimental toggles, no `-beta` module versions. If something is only possible experimentally, substitute a simpler stable solution and note it in the task report.
- Player-facing text is German, in `packs/RP/texts/de_DE.lang`; `en_US.lang` holds the same keys with the same German values (fallback for devices set to English). Code, identifiers, commits are English.
- Interaction is tap-only in the world. No slot-inventory screens.
- Cooking: cooked at 160 ticks (8 s), burnt at 760 ticks (8 s + 30 s).
- Errors only cost ingredients. No damage, no penalties.
- Station and guest state belongs to the world, never to a player (two players in one world must work).
- Stations and furniture break normally; a broken station drops its contents. Guests are invulnerable.
- Vanilla villager geometry, texture and sounds may be reused. Vanilla reference packs: `C:\XboxGames\Minecraft for Windows\Content\data\{behavior_packs,resource_packs}\vanilla_1.26.62`.
- Art: generated 16×16 pixel sprites; raw/burnt variants may be recolors.
- The agent cannot run Minecraft. In-game checks are **human checkpoints**: stop, hand the checklist to the user, wait for their result.

## Review Focus

1. **A station is broken while it holds something** → its contents drop as items and its stored state is removed (Task 4 `*Drops` tests, Task 5 break handler).
2. **Chair, table or bell is broken while a guest sits there** → the guest leaves, no stored state stays behind, a new guest can come once the seat exists again (Task 7 `seatStillValid` test, Task 8).
3. **The world is closed mid-cooking or while a guest waits** → after reload the patty continues from its stored tick count and the guest still waits with the same wish (Task 4 `grillTick` accumulates; Task 5 store round-trip test; Task 8 state on entity dynamic properties).
4. **The player's inventory is full when a station hands something out** → the item drops at the player's feet, never vanishes (Task 5 `giveOrDrop` test).
5. **Wrong thing at the wrong place** (second patty on a full grill, a non-dish on a table, a dish on a table with no waiting guest, a tool on the counter) → nothing is consumed, a short hint appears (Task 4 and Task 7 reducer tests).

### Task 4: Station reducers (pure logic)

**Files:**
- Create: `packs/BP/scripts/logic/stations.js`
- Test: `tests/stations.test.js`

**Interfaces:**
- Consumes: `cookStage`, `evaluateAssembly` (Task 3).
- Produces (all pure; `held` is the held item's id or `null`):

```js
/** @typedef {{ state: any, take?: boolean, give?: string, hint?: string, sound?: string }} Result
 *  take: consume one held item. give: item id handed to the player.
 *  hint: lang key for the action bar. sound: sound id to play at the block. */
GrillState   = { occupied: boolean, ticks: number }          // initial { occupied:false, ticks:0 }
BoardState   = { item: string | null }
CounterState = { items: string[] }                           // max COUNTER_MAX = 8
grillInteract(state, held): Result     grillTick(state, dt): GrillState
grillView(state): 'empty'|'raw'|'cooked'|'burnt'             grillDrops(state): string[]
boardInteract(state, held): Result     boardView(state): 'empty'|'tomato'|'tomato_slices'   boardDrops(state): string[]
counterInteract(state, held): Result   counterDrops(state): string[]
counterView(state): { bun: boolean, patty: 'none'|'raw'|'cooked'|'burnt', lettuce: boolean, tomato: 'none'|'whole'|'slices', cheese: boolean }
INITIAL = { grill, board, counter }    // fresh states
```

Rules (each line is one test):

**Grill**
- empty + `raw_patty` → occupied, ticks 0, `take`, sound `kochmod.sizzle`
- occupied + `raw_patty` → state unchanged, hint `kochmod.hint.grill_full`, no `take`
- occupied + `spatula` → gives `raw_patty` / `cooked_patty` / `burnt_patty` by `cookStage(ticks)`, grill empty
- occupied + anything else or empty hand → unchanged, hint `kochmod.hint.need_spatula`
- empty + anything else (including `cooked_patty`, `spatula`, empty hand) → unchanged, no fields set
- `grillTick` adds `dt` only when occupied and caps ticks at `BURNT_AT`; ticking 16×10 from 0 gives view `cooked`
- `grillDrops`: empty → `[]`; occupied at 200 ticks → `['kochmod:cooked_patty']`

**Board**
- empty + `tomato` → item `tomato`, `take`
- holding `tomato` on board + `knife` → item `tomato_slices`, sound `kochmod.chop`
- `tomato_slices` on board + `knife` → unchanged
- occupied + empty hand → gives the item, board empty
- occupied + `tomato` → hint `kochmod.hint.board_full`, no `take`
- empty + `lettuce` (not cuttable) → unchanged
- `boardDrops` returns the item or `[]`

**Counter**
- accepts exactly the 8 ingredient ids; each adds to `items`, `take`
- with 8 items + ingredient → hint `kochmod.hint.counter_full`, no `take`
- `knife`, `spatula`, any dish → unchanged, no `take`
- empty hand with ≥1 item → gives `evaluateAssembly(items)`, items `[]`, sound `kochmod.plate`
- empty hand with 0 items → unchanged
- `counterView`: patty shows the most recently added patty kind; tomato `slices` wins over `whole` when both present
- `counterDrops` returns the items

- [ ] **Step 3: Implement `stations.js`.** Reducers never mutate their input.

## Decisions made in this plan (not in the spec)

- Crates open a picture menu (one button per item) instead of handing out items directly. A category crate holds several items, so some choice is needed; a button list with pictures is not a slot inventory.
- A crate tap gives 4 ingredients or 1 tool.
- Removing a patty from the grill requires the spatula; an empty hand shows a hint.
- Chairs turn toward an adjacent table automatically; the child does not have to place them in the right direction.
- Ringing the bell calls the next guest immediately.
- Stage 1 has one guest per bell at a time (several guests come with Etappe 3).
- Dishes restore hunger 8, a failed dish 1.
